# APQB Computer の実装範囲と動作検証

APQB-PCは、スマホの既存OS・JavaScriptランタイムの上にあるホスト型仮想計算環境です。物理PCの全デバイスやOSをゼロから実装したものではありません。以前のPC部品一覧には、未実装の機能を完成した部品のように見せる表示があり、訂正しました。

## 今回修正した点

| 対象 | 問題 | 修正 |
| --- | --- | --- |
| CPU | 部品画面とプログラムごとのVMが別物 | PCが1個のQVM64を所有。起動検査とアプリの実行に使う。レジスタ・実行数・失敗を実体から表示 |
| RAM | 整数RAMが画面になく、QALLOCがOSの空きメモリを無視 | 4096×64-bitの論理RAMを表示。APQBはOSと共通の有限プールへ接続 |
| ストレージ | 64 MiBは表示のみ | JSON全体のUTF-8サイズを計上し、書込/追記/ディレクトリ作成時に容量チェック・失敗時ロールバック |
| CPUとディスク | QVMから保存データへアクセス不可 | READ/WRITE命令でQubitFS内の64-bit整数ファイルを読み書き |
| 復元 | 再起動でPIDが戻り、過去の結果を上書きし得る | 保存済みの結果より大きなPIDから開始。ファイル変更の通知を保存処理へ接続 |
| GPU/NPU | 未実装なのに256レーンと表示 | 架空のレーン数を削除。スマホではCPUバックエンドのみと明示 |
| 電源と冷却 | メモリ使用量から作った任意のW/℃/ファン値 | 数値を削除。ホスト管理・未計測と表示 |
| 通信と音声 | Wi-Fi/Bluetooth/LAN/音声を実装済みのように表示 | HTTP(S)はホストfetchを使用。低レベル通信・音声ドライバは未実装と表示 |
| Python版 | QVMや未強制のSSD容量があるように表示、割当失敗時のリーク | Python回路実行サービスであることを明記。未実装・未計測値は表示しない。初期状態を検証してからメモリを確保 |

Python版の `gpu` は従来のAPI名称ですが、現在はNumPyによるCPUベクトル化です。CuPyをインストールするだけでGPU実行に変わるコードではありません。Python版には今回QVM CPUやストレージクォータを移植していません。

## 再現できる操作

スマホ版 Terminal:

```sh
qvm /home/user/Examples/pc-check.qasm
cat /home/user/Documents/pc-result.txt
hardware
open computer
```

演算6×7→RAM STORE/LOAD→APQB測定で1→加算→ディスク保存→読戻しの順に実行し、43を返します。リロード後も保存ファイルは残り、CPUの一時RAMは初期化されます。任意のqasmファイルはTextEditのSave & Runでも同じCPUで動きます。

## 検証の範囲

Jestでは一連の実行とスナップショット復元、64-bit整数精度、共有APQBプール不足、HALT/ゼロ除算/無限ループ/保存エラー後の解放、UTF-8クォータ、満杯時の元データ維持、結果保存失敗のログ、保存変更イベントを検証します。Pythonは割当失敗時のメモリ保持と表示の正確性を含む既存テストを実行します。

今回、TypeScript型検査・Jest・Python unittest・Webビルドを実行しました。ローカルブラウザ本体のダウンロードがタイムアウトしたため、今回の画面操作・実ブラウザのリロード検証は未完了です。保存と再起動はカーネルのスナップショット往復テストで確認しています。iPhone Safari・Android/iOSネイティブ実機検証も未実施です。

## 残っているもの

QVM上でOSカーネル全体を実行するブートローダ、割り込み・MMU・仮想デバイス用ドライバ、ARM/x86バイナリ互換、GPU/NPU実演算、音声入力出力、Macアプリ互換はありません。描画やキー入力はReact Native/ブラウザが担当します。Homebrew/Claude Codeは従来のホスト連携のままで、仮想CPUがネイティブ実行ファイルを動かすわけではありません。性能向上や量子優位性も未検証です。
